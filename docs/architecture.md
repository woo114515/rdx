# 系统架构

## 设计目标

三个 Demo 独立启动，但共享硬件接入、机器人状态和安全控制。算法节点不直接访问串口或相机设备；厂商驱动负责转换为标准 ROS 消息，便于替换驱动和离线测试。

```text
MS200P ──> 雷达驱动 ──> SLAM / 定位 / 动态避障 ─┐
IMX219 ──> 相机驱动 ──> 颜色与柱体感知 ───────┤
编码器/IMU ──────────> 里程计与状态估计 ──────┼─> Demo 行为节点
                                                    │
Demo 速度请求 ──> 安全仲裁（超时/急停/限速） ────┴─> 底盘驱动
```

安全仲裁是所有运动命令的唯一出口。底盘接口、坐标系和话题名称将在首次开机检查后记录，不能依据产品宣传页猜测。

## 计划模块

| 模块 | 责任 |
| --- | --- |
| Bringup | 启动厂商驱动、静态 TF 和硬件配置 |
| Base control | 8 字轨迹、速度约束和停止行为 |
| Navigation | 建图、地图管理、定位、规划与避障 |
| Perception | 相机标定、颜色分类、柱体检测和雷达关联 |
| Sorting | 搜索、目标选择、叉形结构对准和推动状态机 |

ROS 包名统一使用 `rdx_` 前缀。只有跨包确有需要时才创建自定义消息；优先复用 `geometry_msgs`、`nav_msgs`、`sensor_msgs` 和标准动作接口。

## 坐标与配置

预期采用 `map -> odom -> base_link` 的标准 TF 链，并为雷达、相机建立固定外参。最终帧名以实机 TF 为准。速度、距离阈值、颜色阈值、场地边界和堆放策略必须通过 YAML 参数配置，禁止写死在节点代码中。
