# Task 2 建图与自主导航完成日志（2026-09-05）

## 1. 范围与结论

Task 2 的目标是让 ROSMASTER X3 使用 MS200P 完成二维建图、保存和加载地图、在静态地图中定位并执行自主导航，为后续固定多点巡逻提供基础。2026-09-05 已完成从雷达、底盘反馈、TF、建图、地图跨机显示、AMCL 定位、全局规划到 DWB 控制和底盘执行的完整链路复现，并实际完成单目标导航。

本阶段可以作为 Task 3 的开发基础，但“突然出现障碍物时的快速制动”仍有已知缺陷，已明确搁置，不能视为通过动态避障安全验收。

## 2. 运行架构

- 机器人：RDK X5，TROS/ROS 2 Humble，运行底盘、MS200P、EKF、地图和 Nav2 节点。
- 虚拟机：Ubuntu 22.04 + ROS 2 Humble，运行 RViz；桥接到机器人所在局域网。
- ROS 域：`ROS_DOMAIN_ID=99`，桥接网络下使用普通 DDS 发现，不设置 `ROS_DISCOVERY_SERVER`。
- 主要接口：`/scan`、`/odom`、`/tf`、`/map`、`/navigate_to_pose`、`/plan`、`/local_plan`、`/cmd_vel`、`/vel_raw` 和 `/driver_health`。

## 5. 已知问题与边界

1. DWB 面对突然出现的近距离障碍时倾向继续转弯寻找绕行轨迹，从检测到完全停止约 2 秒。当前没有独立 Collision Monitor 紧急制动层，此问题已搁置，恢复处理前不得按正常速度验证动态人员避障。
2. 旋转时仍可能出现雷达点云与地图短时错位。已降低角速度并调整 EKF，但激光扫描运动畸变尚未从驱动或时间同步层彻底解决。
3. footprint 曾被错误放大到 `0.36 m × 0.26 m`，会导致本可通过的狭窄区域被判定不可行。已恢复为 `0.30 m × 0.20 m`，仍需在原卡点进行低速回归测试。
4. 厂商 MS200P 节点在退出时偶尔报告 buffer overflow；正常扫描阶段未见对应数据中断。
5. `patrol_points.py` 没有超时、取消和失败恢复机制，且提示文字写成“四个目标点”，而实际启用了三个点。它只能作为后续多点巡逻测试样例。
6. 实机地图和 rosbag 属于现场数据，不应未经筛选直接提交到代码仓库；继续录包前检查根分区剩余空间。
